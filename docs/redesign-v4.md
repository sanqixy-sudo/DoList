# 第四轮：批量整理与回收站

今天、收件箱、计划和项目的列表模式支持批量整理。删除任务改为移入回收站，可以撤销或稍后恢复。

## 使用方式

- 点击“批量整理”，用独立的选择框勾选任务。完成状态框不会被当作选择框。
- “全选当前页面”包含当前范围内的未渲染任务、已完成任务和折叠分组，并显示总数。切换页面或项目后清除选择。
- 可以批量加入今天、设置或清除计划日期、移动项目、标记完成、移入回收站。计划日期不会覆盖截止时间。
- 工具栏与任务列表分开滚动。多选时暂停行内编辑和拖动排序；失败保留选择及输入，成功后清空选择。
- 普通任务删除后显示“撤销移入”。也可以从侧栏“回收站”搜索、勾选并恢复任务。
- 永久删除仅能对回收站中的任务操作，确认中显示任务数量，并明确同时删除子任务、提醒和附件。没有自动清理期限。

## 数据行为

新增迁移 `005_task_trash`，以 `deleted_at` 保存回收站状态。旧数据库迁移前生成备份。

正常列表、搜索、详情读取和提醒调度排除回收站任务。回收站期间保留任务状态、日期、历史完成时间、子任务、标签、提醒及附件文件；阻止普通任务和子任务、附件等编辑入口修改已删除任务。恢复后的未发送提醒继续按原时间参与调度，已到期的提醒可能立即触发。

删除项目会在同一事务中将其全部任务归入收件箱并移入回收站，再删除项目。已在回收站的任务保留原删除时间。项目本身不能恢复，任务恢复到收件箱。

批量写入先验证全部任务、目标项目和字段，再用事务与预编译语句提交。任一写入失败则整体回滚。单项编辑、排序与批量变更共用写入队列；已删除任务的延迟响应不能重新加入活动列表。

## 验证

```sh
npm run lint
npm test
npm run test:ui
```

- 15 项核心测试通过：旧库迁移和重启、独立计划日期、注入中途写入失败后回滚、历史完成时间、项目删除保护、附件和关系恢复、提醒暂停、永久删除限制、3000 项批量操作及状态竞争。
- 20 项真实 Electron 界面检查通过：包括原有列表、日历、看板回归，1601 项选择/移入/恢复、回收站虚拟滚动与键盘首尾导航、批量和恢复失败后的重试、移动项目、完成、撤销、搜索、永久删除取消/确认和 800×600 深色窗口。
- 界面测试使用独立临时数据，不改用户数据库。日志中的 Injected update/bulk/restore failure 是主动注入的失败场景。

## 范围

多选入口目前限于列表模式；日历、看板和时间线保留现有交互，单项删除共用回收站能力。回收站提供摘要与恢复操作，完整编辑在恢复后进行。回收站卡片使用虚拟列表，但数据目前仍一次读取；本轮未对完整应用冷启动作新的性能测量。
