# 第五轮：备份恢复、统一反馈与性能整理

本轮完成备份恢复、操作反馈、界面精修、启动与搜索优化，以及相关代码拆分。延续“个人效率优先”和“计划日期独立于截止时间”的规则。

## 备份与恢复

在“设置 → 备份与恢复”中导出完整备份，或选择一份备份预览后恢复。

- 备份包含数据库中的任务、项目、项目组、标签、子任务、提醒、回收站和附件文件。
- 界面偏好与专注统计仍属于当前设备，不在任务备份中。
- 预览显示文件名、创建时间、任务数、回收站任务数、项目数和附件数。
- 用户核对内容并勾选替换说明后，才可以执行“恢复并替换任务数据”。
- 恢复前自动导出当前数据到用户数据目录的 `backups` 子目录。自动备份失败时停止恢复。
- 先校验结构、数据库完整性、外键及附件哈希，再将附件写入新的受控目录，最后替换数据库文件。备份携带的附件绝对路径不会用于写入。
- 预览与恢复之间文件被替换、附件缺失、文件损坏或磁盘写入失败时，当前数据库保持原状。
- 恢复后重新加载页面并显示自动备份路径。可以通过同一恢复入口选择这份自动备份，恢复到覆盖前的状态。

备份是版本 1 的 `.dolist-backup` 文件，使用 gzip 封装数据库和附件。当前支持与本版数据库表结构一致的备份，限制压缩文件不超过 256 MiB、解压内容不超过 512 MiB，附件原始总量不超过 256 MiB。大备份的校验和压缩目前在主进程同步完成。旧附件目录和自动备份不自动清理，以保留恢复余地。

交互决策采用 `product-design` 的 `rule/name-object-scope-consequence`、`rule/irreversible-action-safeguard`：在执行覆盖前显示范围和结果，并提供恢复前备份。

## 统一撤销和保存反馈

完成状态、计划日期、截止时间、项目移动及优先级调整，共用顶部操作提示和最近一次操作撤销。列表、详情、右键菜单、看板和批量操作接入相同机制；回收站的撤销移入也使用这一提示区域。

撤销只恢复本次变更的字段，保留之后补充的备注等无关内容。任一目标任务的相关字段再次变化、任务已删除或原项目不存在时，整个批次不撤销，不覆盖新内容。撤销记录仅保留在当前运行会话，新的可撤销操作替代上一次记录；回收站仍可长期恢复。

保存错误明确指出任务和未保存内容。详情中的标题、备注及日期等字段输入会在失败后保留，关闭详情再打开仍可重试。成功后清除过期错误提示。

交互依据：`rule/undo-only-when-honest`、`rule/preserve-user-input`、`rule/error-states-recovery`。

## 界面和交互

- 回收站卡片从 180px 的虚拟行改为 112px，减少留白；窄窗口把恢复和永久删除按钮竖向排列。
- 多选工具栏按计划、项目、完成与清理分组；保持独立于任务列表滚动。
- 操作提示使用 140ms 的轻微淡入位移，按钮提供按下反馈，并尊重系统“减少动态效果”设置。
- 搜索支持重试、结果上限说明、空结果提示。方向键选择时滚动跟随，打开前重新读取任务，避免搜索旧结果把已删除任务带回列表。
- 设置、快速添加等弹窗互相冲突的快捷键受到限制，避免恢复确认时意外打开另一个功能。

## 启动与搜索

详情、快速添加、搜索、设置、专注和快捷键帮助按需加载。专注组件在首次打开后保持挂载，关闭面板仍继续计时。前端生产构建开启 esbuild 压缩。没有新迁移时，启动不再重复导出重写整个数据库。

3000 项任务，使用生产 main/preload/renderer，独立用户数据目录，每组启动 3 个新 Electron 进程。窗口隐藏，禁用全局快捷键，没有清除操作系统磁盘缓存。

| 指标 | 第五轮前 | 最终构建 |
| --- | --- | --- |
| 前端主 JavaScript 文件 | 1104.77 KB | 408.58 KB |
| 新进程到首条任务可见 | 736–800 ms，中位数 765 ms | 606–685 ms，中位数 617 ms |
| 输入搜索词到显示结果 | 213–248 ms，中位数 232 ms | 97–117 ms，中位数 117 ms |
| 搜索 IPC | 约 4–9 ms | 约 3–8 ms |

主文件大小是磁盘上的实际 JS 文件，未使用 gzip；减少同时来自代码拆分和生产压缩。搜索防抖从 180ms 调整为 80ms，是交互等待减少的主要原因。

最终版本首次切到看板约 21–25ms、日历约 18–31ms，回到列表约 12–21ms，终点是对应视图 DOM 出现，不等于所有绘制和动画结束。此前未采集相同的切换基线，不作前后提升对比。

这些是本机小样本结果。中间一次启动复测曾出现 698–980ms 的波动，因此不把最终中位数差异当作所有机器或冷缓存下的速度保证。

复现：

```sh
npm run benchmark
npm run benchmark:startup
```

第二个命令使用第一个命令生成的隔离 3000 项数据库。原始数据保存在 `.audit/startup-before-round5.json`、`.audit/startup-final-round5.json`。

## 勾选交互修正

多选模式下，选择框替换同一列的完成框，每行只显示一个勾选控件；退出多选恢复完成框。选择、点击正文或按空格键只改变批量选择，不修改完成状态。统一选择框样式并增加点击区域；已完成和已取消任务用文字补充状态。

新增勾选专项回归后，24 项 Electron 界面检查通过，包含单控件数量、位置对齐、鼠标/正文/空格键选择，以及退出多选后完成状态保持不变。
