# 第二轮：大列表性能与计划页

## 完成的改动

- 超过 80 条任务的分组使用虚拟列表，只渲染视口附近的行。保留拖动项与当前键盘焦点，切换项目重新定位到顶部。
- 支持上下方向键逐项查看，Home / End 跳到分组首尾；在排序柄上使用 Alt + ↑ / ↓ 调整顺序。鼠标拖动继续可用。
- 计划页分为待重新安排、今天、明天、未来 7 天和之后，组内按日期排序。以计划日期为准，没有计划日期才使用截止日期，不改动任务原字段。今天和明天不会在“未来 7 天”重复出现。
- 计划页使用固定的日期顺序，因此不提供手动拖动排序；今日、收件箱和项目列表保留排序功能。
- 批量排序使用一个事务和预编译语句，成功后只安排一次磁盘保存；失败整体回滚。连续排序请求按顺序提交。
- 列表拆成页面、分组和任务行三个组件，便于继续维护。

## 性能结果

Windows 本机、同一组 3,000 条模拟任务、真实 Electron 隔离窗口、关闭 GPU。页面加载测量 3 次取中位数，数据库排序测量 5 次取中位数。

| 指标 | 优化前 | 本轮最终复测 |
| --- | ---: | ---: |
| 页面加载至首屏绘制 | 8.60 秒 | 0.66 秒 |
| 初始挂载任务行 | 3000 | 17 |
| 3,000 条任务排序 | 106.7 毫秒 | 29.4 毫秒 |

首轮优化复测的首屏中位数为 0.21 秒，最终复测为 0.66 秒，反映本机负载波动。此指标从窗口加载页面开始，不包括 Electron 启动和数据库初始化，不代表完整冷启动耗时。未把两帧滚动观测转换为 FPS，也未声称数据库读取变快。

原始结果位于本地 .audit/benchmark-baseline.json、.audit/benchmark-optimized.json 和 .audit/benchmark-current.json。测试均使用独立数据库。

## 验证与运行

```sh
npm run dev
npm run lint
npm test
npm run test:ui
npm run benchmark
```

核心测试覆盖日期分组跨年、事务回滚、排序重启保留及原有数据规则。Electron 检查加入 1,500 条任务的首尾滚动、Home / End、鼠标拖动、键盘排序、完成末尾任务，以及折叠前置分组后的定位。

benchmark 会构建当前版本并写入 .audit/benchmark-current.json。测试脚本自动退出，截图和测试数据库保存在 .audit/，不会使用个人数据库。本轮没有新增数据结构迁移。
